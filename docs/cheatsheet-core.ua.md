## Зрізи (slices)

### Визначення

Зріз — це невеликий дескриптор безперервної частини базового масиву. Концептуально він містить:

- вказівник на перший видимий елемент backing array;
- довжину, яку повертає `len`;
- місткість, яку повертає `cap`.

Зріз не зберігає елементи сам. Під час копіювання значення зрізу копіюється лише цей дескриптор, тому
два зрізи можуть посилатися на один backing array.

```go
array := [4]int{10, 20, 30, 40}
slice := array[1:3] // [20 30]

slice[0] = 99
fmt.Println(array) // [10 99 30 40]
```

### `len` і `cap`

`len(s)` — кількість елементів, які наразі видно через `s`.

`cap(s)` — кількість елементів, доступних від початку `s` до кінця його backing array. Це не
обов'язково місткість початкового зрізу.

```go
s := []int{2, 3, 5, 7, 11, 13}
fmt.Println(len(s), cap(s)) // 6 6

s = s[:4]
fmt.Println(len(s), cap(s)) // 4 6

s = s[2:]
fmt.Println(len(s), cap(s)) // 2 4
```

Повторне slicing може змінити довжину без виділення пам'яті. Розширити зріз можна лише до його
місткості.

### `append`

`append` повертає результуючий зріз, тому його результат завжди слід зберігати.

```go
s := []int{1, 2}
s = append(s, 3)
```

Якщо зріз має вільну місткість, `append` може повторно використати його backing array. Тоді інші
зрізи, що спільно використовують цей масив, можуть побачити записані елементи.

```go
a := make([]int, 2, 4)
a[0], a[1] = 10, 20
b := append(a, 30)

b[0] = 99
fmt.Println(a) // [99 20]
fmt.Println(b) // [99 20 30]
```

Якщо місткості недостатньо, `append` виділяє новий backing array і копіює до нього попередні
елементи. Не покладайтеся на конкретну формулу зростання місткості: це деталь реалізації.

```go
a := make([]int, 2, 2)
a[0], a[1] = 10, 20
b := append(a, 30)

b[0] = 99
fmt.Println(a) // [10 20]
fmt.Println(b) // [99 20 30]
```

### Аліасинг subslice

Subslice зазвичай спільно використовує backing array з початковим зрізом. `append` до subslice може
перезаписати елементи, які видно через інший зріз.

```go
a := []int{1, 2, 3, 4}
b := a[:2] // len=2, cap=4
b = append(b, 99)

fmt.Println(a) // [1 2 99 4]
```

Використовуйте повний slice expression, щоб обмежити місткість, доступну subslice. Він змусить
наступний `append` виділити пам'ять, але не копіює вже наявні елементи.

```go
a := []int{1, 2, 3, 4}
b := a[:2:2] // len=2, cap=2
b = append(b, 99)

fmt.Println(a) // [1 2 3 4]
fmt.Println(b) // [1 2 99]
```

Повний slice expression доречний, коли зріз має залишитися представленням початкових даних, але
код, що викликає, не повинен розширювати його в решту backing array. Коли потрібна повна
незалежність, використовуйте копію.

### Копіювання та клонування

`copy(dst, src)` копіює до `min(len(dst), len(src))` елементів і повертає кількість скопійованих
елементів. Довжину `dst` він не змінює.

```go
src := []int{1, 2, 3, 4}
dst := make([]int, 2)
n := copy(dst, src)

fmt.Println(n, dst) // 2 [1 2]
```

Незалежний клон, який зберігає відмінність між `nil` і порожнім зрізом:

```go
func Clone[T any](s []T) []T {
	if s == nil {
		return nil
	}

	out := make([]T, len(s))
	copy(out, s)
	return out
}
```

`append([]T(nil), s...)` — також поширений ідіоматичний спосіб клонування. Однак для порожнього
не-nil зрізу він може повернути nil-зріз; використовуйте його, лише якщо ця відмінність неважлива.

### `nil` і порожні зрізи

І nil-зріз, і порожній зріз мають нульову довжину: за ними можна ітеруватися через `range` та
передавати їх до `append`. Але це різні значення.

```go
var nilSlice []int
emptySlice := []int{}

fmt.Println(len(nilSlice), nilSlice == nil)     // 0 true
fmt.Println(len(emptySlice), emptySlice == nil) // 0 false
```

Відмінність важлива на межах API. Наприклад, `encoding/json` кодує nil-зріз як `null`, а порожній —
як `[]`.

Щоб перевірити порожність, використовуйте `len(s) == 0`, якщо тільки API спеціально не розрізняє nil
і порожній зріз.

### Утримання великого backing array

Маленький subslice зберігає досяжність усього backing array. Тому повернення 10-байтового subslice
від буфера у 100 MB може утримувати в пам'яті приблизно 100 MB.

```go
func firstTenBad() []byte {
	big := make([]byte, 100<<20)
	return big[:10]
}
```

Якщо великий буфер більше не потрібен, скопіюйте малу частину перед поверненням.

```go
func firstTenGood() []byte {
	big := make([]byte, 100<<20)
	small := make([]byte, 10)
	copy(small, big[:10])
	return small
}
```

### Звичайні операції та володіння даними

Операції in-place повторно використовують backing array і можуть змінювати елементи вхідного зрізу.
Функція, що повертає новий зріз, виділяє окрему пам'ять і не змінює вхідні дані.

```go
// In place: the input's backing array is modified.
func DeleteAt[T any](s []T, i int) []T {
	copy(s[i:], s[i+1:])
	var zero T
	s[len(s)-1] = zero // release a reference held in the unused tail, if any
	return s[:len(s)-1]
}

// New slice: the input is unchanged.
func DeleteAtNew[T any](s []T, i int) []T {
	out := make([]T, 0, len(s)-1)
	out = append(out, s[:i]...)
	return append(out, s[i+1:]...)
}
```

Документуючи або проєктуючи API, чітко зазначайте, чи може функція утримувати, змінювати або
повторно використовувати зріз, переданий кодом, що викликає.

### `range` за зрізами

Значення, яке повертає `range`, є копією елемента. Щоб змінити елементи, звертайтеся до них за
індексом.

```go
s := []int{1, 2, 3}
for _, v := range s {
	v *= 10 // changes only the copy
}

for i := range s {
	s[i] *= 10 // changes the slice element
}
```

Кількість ітерацій визначається на початку `range`. Додавання елементів під час цього циклу не
змушує його ітеруватися за доданими елементами; уникайте цього патерну, якщо така поведінка не
задумана навмисно.

### Конкурентний доступ

Зрізи небезпечні для одночасної зміни. Якщо goroutines спільно використовують зріз і принаймні одна
з них у нього пише, синхронізуйте доступ або передайте кожній goroutine незалежну копію.

### Запитання для повторення

1. Що містить дескриптор зрізу?
2. Чому зміна одного зрізу може змінити інший?
3. Коли `append` може повторно використати backing array, а коли мусить виділити новий?
4. Що змінює `s[low:high:max]`, а чого не змінює?
5. Чому для `copy` потрібен destination ненульової довжини?
6. Коли відмінність між nil і порожнім зрізом має практичне значення?
7. Як маленький зріз може утримувати велике виділення пам'яті?

### Відповіді на запитання для повторення

1. Дескриптор зрізу концептуально містить вказівник на backing array, довжину та місткість.
2. Після копіювання або створення subslice обидва зрізи зазвичай і далі вказують на один backing
   array. Тому запис через один зріз змінює цей масив і може бути видно через інший.
3. `append` може повторно використати backing array, якщо підсумкова довжина вміщується в поточну
   місткість. Якщо місткості недостатньо, він мусить виділити новий масив.
4. `s[low:high:max]` задає довжину результуючого зрізу як `high-low`, а місткість — як `max-low`.
   Вираз обмежує подальше розширення через цей зріз, але не копіює елементи й не припиняє спільне
   використання вже видимих елементів.
5. `copy` копіює лише в наявні елементи destination — до меншої з довжин source і destination. У nil
   або zero-length destination немає елементів, у які можна скопіювати дані.
6. Відмінність важлива, коли API враховує nilness: наприклад, під час JSON-кодування (`null` або `[]`),
   або коли nil сам має значення в API. В інших випадках для перевірки порожності використовуйте
   `len(s) == 0`.
7. Дескриптор зрізу зберігає досяжність backing array. Маленький subslice усе ще вказує всередину
   початкового великого масиву, тому збирач сміття не може звільнити його, доки subslice досяжний.
   Скопіюйте потрібні елементи в новий зріз, щоб звільнити великий масив.

## Мапи (maps)

### Базові операції

Мапа пов'язує порівнювані ключі зі значеннями: `map[K]V`. Використовуйте літерал, якщо початкові
елементи вже відомі, або `make`, якщо мапа починається порожньою.

```go
prices := map[string]int{"apple": 10}
stock := make(map[string]int)
```

Значення читається через `m[key]`. Якщо ключ відсутній, вираз повертає zero value типу значень
мапи. Для `int` це `0`.

```go
fmt.Println(prices["apple"]) // 10
fmt.Println(prices["pear"])  // 0
```

Той самий синтаксис присвоєння використовується для вставки й оновлення. Присвоєння новому ключу
вставляє його, а присвоєння наявному замінює значення.

```go
stock["apple"] = 3 // вставка
stock["apple"] = 5 // оновлення
```

`delete(m, key)` видаляє ключ. Безпечно видаляти й ключ, якого вже немає. `len(m)` повертає поточну
кількість елементів мапи.

```go
delete(stock, "apple")
fmt.Println(len(stock))
```

Zero value під час читання відсутнього ключа не дає відрізнити його від ключа, що явно зберігає zero
value. Lookup у формі comma-ok, який розв'язує цю проблему, належить до наступної групи про maps.

2. Що стається під час читання відсутнього ключа через `m[key]`?
3. Яка операція і додає новий ключ, і оновлює наявний?
4. Що стається, якщо передати в `delete` ключ, якого вже немає?
5. Що повертає `len(m)`?

### Відповіді на запитання для повторення

1. Використовуйте літерал, наприклад `map[string]int{"apple": 10}`, для початкових елементів і `make(map[string]int)` для порожньої мапи, готової до запису.
2. Повертається zero value типу значень мапи.
3. `m[key] = value` вставляє ключ, якщо його немає, і замінює значення, якщо він уже є.
4. Нічого; видаляти відсутній ключ безпечно.
5. Поточну кількість пар ключ-значення.

### Надійний lookup і стан мапи

Звичайний lookup не відрізняє відсутній ключ від ключа, у якому зберігається zero value. Коли ця
відмінність важлива, використовуйте форму comma-ok.

```go
stock := map[string]int{"apple": 0}

quantity, present := stock["apple"] // 0, true
missing, present := stock["pear"]   // 0, false
```

Nil map і порожня ініціалізована мапа мають довжину нуль, і їх можна безпечно читати. Lookup з обох
повертає zero value типу значень; comma-ok повертає `false` для відсутнього ключа.

```go
var nilStock map[string]int
emptyStock := make(map[string]int)

fmt.Println(len(nilStock), nilStock == nil)     // 0 true
fmt.Println(len(emptyStock), emptyStock == nil) // 0 false
```

Ключова відмінність — запис: присвоєння в nil map спричиняє panic, а порожня мапа, створена через
`make`, готова до вставки й оновлення. Якщо потрібно перевірити лише порожність, використовуйте
`len(m) == 0`; `m == nil` перевіряйте лише тоді, коли nilness має окреме значення в API.

### Запитання для повторення: надійний lookup і стан

1. Чому `value := m[key]` неоднозначний для мапи з zero-valued entries?
2. Що означають два результати `value, ok := m[key]`?
3. Які базові операції безпечні для nil map?
4. Що стається під час присвоєння в nil map?
5. Коли слід використовувати `len(m) == 0` замість `m == nil`?

### Відповіді на запитання для повторення: надійний lookup і стан

1. Відсутній ключ і наявний ключ зі значенням, рівним zero value типу, обидва дають це zero value.
2. `value` — збережене значення або zero value; `ok` повідомляє, чи є ключ.
3. Безпечні читання, comma-ok lookup, `len` і `delete`. Запис небезпечний.
4. Виникає panic під час виконання.
5. Використовуйте `len(m) == 0` для перевірки порожності; `m == nil` — лише якщо API надає nil окремого значення.

### Порядок обходу

Порядок, який створює `range` за мапою, не визначений. Його не можна використовувати в логіці
програми або як очікування в тесті. Якщо для виводу потрібен стабільний порядок, зберіть ключі та
відсортуйте їх.

```go
keys := make([]string, 0, len(counts))
for key := range counts {
	keys = append(keys, key)
}
sort.Strings(keys)
```

Тест для невпорядкованого результату має порівнювати склад елементів і довжину або порівнювати
нормалізований відсортований результат. Не вважайте один спостережений порядок мапи постійним.

### Поширені патерни

Для підрахунку використовується zero value типу `int`, тому новий ключ можна збільшувати без
попереднього lookup.

```go
counts := make(map[string]int)
for _, word := range words {
	counts[word]++
}
```

Для групування значенням мапи є зріз. `append` працює з nil slice, тому для першого значення групи
не потрібен окремий випадок. Цей приклад групує за довжиною в байтах.

```go
groups := make(map[int][]string)
for _, word := range words {
	groups[len(word)] = append(groups[len(word)], word)
}
```

Індексування перетворює зріз на lookup table. Визначте поведінку для повторюваних ключів: звичайне
присвоєння замінює попередній запис пізнішим.

```go
index := make(map[int]User)
for _, user := range users {
	index[user.ID] = user
}
```

Множину зазвичай представляють як `map[T]struct{}`. Порожня структура позначає належність без
окремого значення.

```go
set := make(map[string]struct{})
set["go"] = struct{}{}
_, hasGo := set["go"]
```

### Запитання для повторення: обхід і патерни

1. Чому порядок обходу мапи не підходить для логіки програми?
2. Як вивести ключі мапи у стабільному порядку?
3. Чому `counts[key]++` може одразу рахувати новий ключ?
4. Чому `groups[key] = append(groups[key], value)` працює для нової групи?
5. Що стається з повторюваними ключами в індексі, побудованому звичайним присвоєнням?
6. Чому `map[T]struct{}` підходить для представлення множини?

### Відповіді на запитання для повторення: обхід і патерни

1. Мова не задає цей порядок, тому він може змінюватися між обходами й запусками.
2. Зібрати ключі у зріз і відсортувати його перед виводом.
3. Відсутній елемент `int`-мапи читається як нуль, а збільшення нуля дає перший лічильник.
4. Відсутній елемент-зріз дорівнює nil, а `append` приймає nil slice.
5. Пізніше присвоєння замінює попереднє значення для цього ключа.
6. Ключі представляють елементи, а `struct{}` — порожнє значення, тому мапа зберігає належність без payload.
