## Срезы (slices)

### Определение

Срез — это небольшой дескриптор непрерывного участка базового массива. Концептуально он содержит:

- указатель на первый видимый элемент backing array;
- длину, которую возвращает `len`;
- ёмкость, которую возвращает `cap`.

Срез не хранит элементы сам. При копировании значения среза копируется только этот дескриптор, поэтому
два среза могут ссылаться на один backing array.

```go
array := [4]int{10, 20, 30, 40}
slice := array[1:3] // [20 30]

slice[0] = 99
fmt.Println(array) // [10 99 30 40]
```

### `len` и `cap`

`len(s)` — количество элементов, видимых через `s` в данный момент.

`cap(s)` — количество элементов, доступных от начала `s` до конца его backing array. Это не
обязательно ёмкость исходного среза.

```go
s := []int{2, 3, 5, 7, 11, 13}
fmt.Println(len(s), cap(s)) // 6 6

s = s[:4]
fmt.Println(len(s), cap(s)) // 4 6

s = s[2:]
fmt.Println(len(s), cap(s)) // 2 4
```

Повторное slicing может изменить длину без выделения памяти. Расширить срез можно только до его
ёмкости.

### `append`

`append` возвращает результирующий срез, поэтому его результат всегда нужно сохранять.

```go
s := []int{1, 2}
s = append(s, 3)
```

Если в срезе есть свободная ёмкость, `append` может переиспользовать его backing array. Тогда другие
срезы, разделяющие этот массив, могут увидеть записанные элементы.

```go
a := make([]int, 2, 4)
a[0], a[1] = 10, 20
b := append(a, 30)

b[0] = 99
fmt.Println(a) // [99 20]
fmt.Println(b) // [99 20 30]
```

Если ёмкости недостаточно, `append` выделяет новый backing array и копирует в него прежние элементы.
Не полагайтесь на конкретную формулу роста ёмкости: это деталь реализации.

```go
a := make([]int, 2, 2)
a[0], a[1] = 10, 20
b := append(a, 30)

b[0] = 99
fmt.Println(a) // [10 20]
fmt.Println(b) // [99 20 30]
```

### Алиасинг subslice

Subslice обычно разделяет backing array с исходным срезом. `append` к subslice может перезаписать
элементы, видимые через другой срез.

```go
a := []int{1, 2, 3, 4}
b := a[:2] // len=2, cap=4
b = append(b, 99)

fmt.Println(a) // [1 2 99 4]
```

Используйте полное slice expression, чтобы ограничить ёмкость, доступную subslice. Оно заставит
последующий `append` выделить память, но не копирует уже существующие элементы.

```go
a := []int{1, 2, 3, 4}
b := a[:2:2] // len=2, cap=2
b = append(b, 99)

fmt.Println(a) // [1 2 3 4]
fmt.Println(b) // [1 2 99]
```

Полное slice expression подходит, когда срез должен остаться представлением исходных данных, но
вызывающий код не должен расширять его в оставшуюся часть backing array. Когда нужна полная
независимость, используйте копию.

### Копирование и клонирование

`copy(dst, src)` копирует до `min(len(dst), len(src))` элементов и возвращает количество скопированных
элементов. Длину `dst` он не изменяет.

```go
src := []int{1, 2, 3, 4}
dst := make([]int, 2)
n := copy(dst, src)

fmt.Println(n, dst) // 2 [1 2]
```

Независимый клон, который сохраняет различие между `nil` и пустым срезом:

```go
func Clone[T any](s []T) []T {
	if s == nil {
		return nil
	}

	out := make([]T, len(s))
	copy(out, s)
	return out
}
```

`append([]T(nil), s...)` — также распространённый идиоматичный способ клонирования. Однако для пустого
не-nil среза он может вернуть nil-срез; выбирайте его, только если это различие несущественно.

### `nil` и пустые срезы

И nil-срез, и пустой срез имеют нулевую длину: по ним можно итерироваться через `range` и передавать
их в `append`. Но это разные значения.

```go
var nilSlice []int
emptySlice := []int{}

fmt.Println(len(nilSlice), nilSlice == nil)     // 0 true
fmt.Println(len(emptySlice), emptySlice == nil) // 0 false
```

Различие важно на границах API. Например, `encoding/json` кодирует nil-срез как `null`, а пустой — как
`[]`.

Чтобы проверить пустоту, используйте `len(s) == 0`, если только API специально не различает nil и
пустой срез.

### Удержание большого backing array

Маленький subslice сохраняет достижимость всего backing array. Поэтому возврат 10-байтового subslice
от буфера в 100 MB может удерживать в памяти примерно 100 MB.

```go
func firstTenBad() []byte {
	big := make([]byte, 100<<20)
	return big[:10]
}
```

Если большой буфер больше не нужен, скопируйте малую часть перед возвратом.

```go
func firstTenGood() []byte {
	big := make([]byte, 100<<20)
	small := make([]byte, 10)
	copy(small, big[:10])
	return small
}
```

### Обычные операции и владение данными

Операции in-place переиспользуют backing array и могут менять элементы входного среза. Функция,
возвращающая новый срез, выделяет отдельную память и не меняет входные данные.

```go
// In place: the input's backing array is modified.
func DeleteAt[T any](s []T, i int) []T {
	copy(s[i:], s[i+1:])
	var zero T
	s[len(s)-1] = zero // release a reference held in the unused tail, if any
	return s[:len(s)-1]
}

// New slice: the input is unchanged.
func DeleteAtNew[T any](s []T, i int) []T {
	out := make([]T, 0, len(s)-1)
	out = append(out, s[:i]...)
	return append(out, s[i+1:]...)
}
```

При документировании или проектировании API явно указывайте, может ли функция удерживать, изменять
или переиспользовать срез, переданный вызывающим кодом.

### `range` по срезам

Значение, которое выдаёт `range`, является копией элемента. Чтобы изменить элементы, обращайтесь к
ним по индексу.

```go
s := []int{1, 2, 3}
for _, v := range s {
	v *= 10 // changes only the copy
}

for i := range s {
	s[i] *= 10 // changes the slice element
}
```

Количество итераций определяется при запуске `range`. Добавление элементов в ходе этого цикла не
заставляет его итерироваться по добавленным элементам; избегайте этого паттерна, если такое поведение
не задумано намеренно.

### Конкурентный доступ

Срезы небезопасны для одновременного изменения. Если goroutines разделяют срез и хотя бы одна из них
в него пишет, синхронизируйте доступ или передайте каждой goroutine независимую копию.

### Вопросы для повторения

1. Что содержит дескриптор среза?
2. Почему изменение одного среза может изменить другой?
3. Когда `append` может переиспользовать backing array, а когда обязан выделить новый?
4. Что меняет `s[low:high:max]`, а что не меняет?
5. Почему для `copy` нужен destination ненулевой длины?
6. Когда различие nil и пустого среза имеет практическое значение?
7. Как маленький срез может удерживать большую аллокацию?

### Ответы на вопросы для повторения

1. Дескриптор среза концептуально содержит указатель на backing array, длину и ёмкость.
2. При копировании или создании subslice оба среза обычно продолжают указывать на один backing
   array. Поэтому запись через один срез изменяет этот массив и может быть видна через другой.
3. `append` может переиспользовать backing array, если итоговая длина укладывается в текущую ёмкость.
   Если ёмкости недостаточно, он обязан выделить новый массив.
4. `s[low:high:max]` задаёт длину результирующего среза как `high-low`, а ёмкость — как `max-low`.
   Выражение ограничивает последующее расширение через этот срез, но не копирует элементы и не
   прекращает совместное использование уже видимых элементов.
5. `copy` копирует только в уже существующие элементы destination — до меньшей из длин source и
   destination. В nil или zero-length destination нет элементов, в которые можно скопировать данные.
6. Различие важно, когда API учитывает nilness: например, при JSON-кодировании (`null` или `[]`), либо
   когда nil сам имеет смысл в API. В остальных случаях для проверки пустоты используйте `len(s) == 0`.
7. Дескриптор среза сохраняет достижимость backing array. Маленький subslice всё ещё указывает внутрь
   исходного большого массива, поэтому сборщик мусора не может освободить его, пока subslice
   достижим. Скопируйте нужные элементы в новый срез, чтобы освободить большой массив.

## Карты (maps)

### Базовые операции

Карта связывает сравнимые ключи со значениями: `map[K]V`. Используйте литерал, если начальные
элементы уже известны, или `make`, если карта начинается пустой.

```go
prices := map[string]int{"apple": 10}
stock := make(map[string]int)
```

Значение читается через `m[key]`. Если ключ отсутствует, выражение возвращает zero value типа
значений карты. Для `int` это `0`.

```go
fmt.Println(prices["apple"]) // 10
fmt.Println(prices["pear"])  // 0
```

Один и тот же синтаксис присваивания служит для вставки и обновления. Присваивание новому ключу
вставляет его, а присваивание существующему заменяет значение.

```go
stock["apple"] = 3 // вставка
stock["apple"] = 5 // обновление
```

`delete(m, key)` удаляет ключ. Безопасно удалять и уже отсутствующий ключ. `len(m)` возвращает
текущее количество элементов карты.

```go
delete(stock, "apple")
fmt.Println(len(stock))
```

Zero value при чтении отсутствующего ключа не позволяет отличить его от ключа, явно хранящего zero
value. Lookup в форме comma-ok, решающий эту проблему, относится к следующей группе по maps.

1. Как создать карту с начальными элементами и пустую карту, готовую к записи?
2. Что происходит при чтении отсутствующего ключа через `m[key]`?
3. Какая операция и добавляет новый ключ, и обновляет существующий?
4. Что происходит, если передать в `delete` уже отсутствующий ключ?
5. Что возвращает `len(m)`?

### Ответы на вопросы для повторения

1. Используйте литерал, например `map[string]int{"apple": 10}`, для начальных элементов и `make(map[string]int)` для пустой карты, готовой к записи.
2. Возвращается zero value типа значений карты.
3. `m[key] = value` вставляет ключ, если его нет, и заменяет значение, если он уже есть.
4. Ничего; удалять отсутствующий ключ безопасно.
5. Текущее количество пар ключ-значение.

### Надёжный lookup и состояние карты

Обычный lookup не отличает отсутствующий ключ от ключа, в котором хранится zero value. Когда это
различие важно, используйте форму comma-ok.

```go
stock := map[string]int{"apple": 0}

quantity, present := stock["apple"] // 0, true
missing, present := stock["pear"]   // 0, false
```

Nil map и пустая инициализированная карта имеют длину ноль, и их можно безопасно читать. Lookup из
обеих возвращает zero value типа значений; comma-ok возвращает `false` для отсутствующего ключа.

```go
var nilStock map[string]int
emptyStock := make(map[string]int)

fmt.Println(len(nilStock), nilStock == nil)     // 0 true
fmt.Println(len(emptyStock), emptyStock == nil) // 0 false
```

Ключевое различие — запись: присваивание в nil map вызывает panic, а пустая карта, созданная через
`make`, готова к вставке и обновлению. Если нужно проверить только пустоту, используйте `len(m) == 0`;
`m == nil` проверяйте лишь тогда, когда nilness имеет отдельный смысл в API.

### Вопросы для повторения: надёжный lookup и состояние

1. Почему `value := m[key]` неоднозначен для карты с zero-valued entries?
2. Что означают два результата `value, ok := m[key]`?
3. Какие базовые операции безопасны для nil map?
4. Что происходит при присваивании в nil map?
5. Когда следует использовать `len(m) == 0` вместо `m == nil`?

### Ответы на вопросы для повторения: надёжный lookup и состояние

1. Отсутствующий ключ и присутствующий ключ со значением, равным zero value типа, оба дают это zero value.
2. `value` — сохранённое значение или zero value; `ok` сообщает, существует ли ключ.
3. Безопасны чтение, comma-ok lookup, `len` и `delete`. Запись небезопасна.
4. Возникает panic во время выполнения.
5. Используйте `len(m) == 0` для проверки пустоты; `m == nil` — только если API придаёт nil отдельный смысл.

### Порядок обхода

Порядок, который создаёт `range` по карте, не определён. Его нельзя использовать в логике программы
или как ожидание в тесте. Если для вывода нужен стабильный порядок, соберите ключи и отсортируйте их.

```go
keys := make([]string, 0, len(counts))
for key := range counts {
	keys = append(keys, key)
}
sort.Strings(keys)
```

Тест для неупорядоченного результата должен сравнивать состав элементов и длину либо сравнивать
нормализованный отсортированный результат. Не считайте один наблюдаемый порядок карты постоянным.

### Распространённые паттерны

Для подсчёта используется zero value типа `int`, поэтому новый ключ можно увеличивать без
предварительного lookup.

```go
counts := make(map[string]int)
for _, word := range words {
	counts[word]++
}
```

Для группировки значением карты служит срез. `append` работает с nil slice, поэтому для первого
значения группы не нужен отдельный случай. Этот пример группирует по длине в байтах.

```go
groups := make(map[int][]string)
for _, word := range words {
	groups[len(word)] = append(groups[len(word)], word)
}
```

Индексирование превращает срез в lookup table. Определите поведение для дублирующихся ключей:
обычное присваивание заменяет прежнюю запись более поздней.

```go
index := make(map[int]User)
for _, user := range users {
	index[user.ID] = user
}
```

Множество обычно представляют как `map[T]struct{}`. Пустая структура обозначает принадлежность без
отдельного значения.

```go
set := make(map[string]struct{})
set["go"] = struct{}{}
_, hasGo := set["go"]
```

### Вопросы для повторения: обход и паттерны

1. Почему порядок обхода карты не подходит для логики программы?
2. Как вывести ключи карты в стабильном порядке?
3. Почему `counts[key]++` может сразу считать новый ключ?
4. Почему `groups[key] = append(groups[key], value)` работает для новой группы?
5. Что происходит с повторяющимися ключами в индексе, построенном обычным присваиванием?
6. Почему `map[T]struct{}` подходит для представления множества?

### Ответы на вопросы для повторения: обход и паттерны

1. Язык не задаёт этот порядок, поэтому он может меняться между обходами и запусками.
2. Собрать ключи в срез и отсортировать его перед выводом.
3. Отсутствующий элемент `int`-карты читается как ноль, а увеличение нуля даёт первый счётчик.
4. Отсутствующий элемент-срез равен nil, а `append` принимает nil slice.
5. Более позднее присваивание заменяет прежнее значение для этого ключа.
6. Ключи представляют элементы, а `struct{}` — пустое значение, поэтому карта хранит принадлежность без payload.
